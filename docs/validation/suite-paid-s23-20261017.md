# S23 Ultra fixed suite, paid round (DeepSeek V4.1 Flash)

Date: 2026-10-17 Dubai. Device: Galaxy S23 Ultra (SM-S918B), Android 16/API 36,
arm64-v8a, serial ending `NAFP`, `ro.kernel.qemu=0`. The user connected the
phone and approved paid requests on it with `deepseek/deepseek-v4.1-flash` on
2026-10-17, then saved the OpenRouter key in the controller's Builder key page.
The key was never read; only the presence of its file was checked by name.

Harness: worker `4d91001a…`, controller `6644ff70…` and controller test APK,
all signed by the project's alpha identity and installed in place over USB.
The controller was a fresh install, so every project here is new. The model
policy is the one in [the A33 paid round](suite-paid-a33-20261017.md): providers
`deepinfra`, `together` and `nebius` only, at most $0.30/$1.20 per million
input/output tokens, low reasoning, `usage.cost` required and at most $0.05,
and the probe stops sending once its cost bound reaches $2.

Before the suite, the six technical-debt probes passed on this phone
(`toolchains/debt-validation/20261017T141105Z-2e4351c2`): held-open snapshot
deadline, project binding, generation completion, local compile and sign,
worker deadline kill and recovery.

Every request used the normal controller screen through `A33SuiteProbe`,
driven by `scripts/suite/suite.py` with the exact previewed context hash.
Generated APKs were verified on the phone and streamed from `run-as` into
`pm install` (debug install, not Android installer consent). Checklists ran
with the controller and worker force-stopped, through accessibility actions
from the controller test APK (`foreignUi`). These are agent observations, not
human acceptance. Raw output: `toolchains/alpha-goal-20261017/<run id>/`.
Run ids start with `s23_` and end in `_20`.
