# A33: recovery after process death and full storage (2026-11-02)

Date: 2026-11-02 Dubai. Device: Galaxy A33 5G (SM-A336E), Android 16/API 36,
USB debug. Controller debug APK `4ed33106…` (main `cb11d7d`) for the process
cases and the first storage cases; `94ef57af…` (`8f4ee43`) for the storage
reruns. Test project RecoveryT1 (`app69cacd34…`), the starter counter. Model
DeepSeek V4.1 Flash (approved for step-run tests). The UI was driven with
`input` taps and `uiautomator dump`, not instrumentation, because Android kills
the app when an instrumentation run ends. Screenshots:
`toolchains/recovery-20261102/`.

Scope set by the user on 2026-11-02: no memory work; storage and heat limits
count as covered; recovery across phones is dropped (the recovery file covers

## Full storage

The disk was filled with `fallocate` inside the controller's own `files/`
folder (all other apps saw a full disk too) and freed with `rm -rf` after each
case: full about 13:21–13:24, 13:25–13:26 and 13:35–13:36. Android trims app
caches by itself when storage is low and frees 1 GB or a few MB within seconds,
so a full disk could not be held for long on this unrooted phone.

| Case | Expected | Actual |
| --- | --- | --- |
| T2b full right after the first build | the run ends without spending more requests; the person is told | partly: the run ended READY_TO_TEST at r2 one second after the fill, but its reply and closing could not be saved, nothing on screen said storage was full, and Undo was not recorded (logged). The kept progress could not add a note later, because the next send added messages to the same chat first. Fixed in `8f4ee43` (below) |
| T2a send with 0 KB free | stop at once with a plain message | pass: the run reached APPLYING, could not save its change, ended `FAILED@r2` after one request with "Your phone's storage is full, so the builder stopped. Changes it saved remain. Free some space on the phone, then send a message to continue." |
| T2d restart with the disk still full | the app opens; nothing is lost | pass: the project opened and wrote T2a's kept chat (message, steps ending "your phone's storage is full"), but closed it with "The builder was closed before it finished", which was wrong. Fixed in `8f4ee43` |
| T2c after freeing space | send and build work | pass: run `READY_TO_TEST@r3v5` with the reply and "Your app is ready." |

`8f4ee43` makes a chat written later close a run that stopped on full storage
with the storage message, and makes a send first write any earlier run's
unsaved chat, refusing with "An earlier reply could not be saved in the chat,
so nothing was sent. If your phone's storage is full, free some space…" when
that fails. Host tests cover the closing line (830 tests, lint clean). Two
reruns on `94ef57af…` filled the disk before sending, one with a top-up loop
every 0.2 s, but Android freed 2 MB and 14 MB in time and both runs finished
normally (r4 v6 and r5 v7). The refusal path is therefore not physically
observed.

## Not covered

- A send refused because an earlier chat is still unsaved (see above).
- A disk that stays full for minutes; Android frees cache space first.
- Real low-memory eviction by the system; `kill -9` and `am kill` stand in.
- Recovery across phones (dropped by the user).
