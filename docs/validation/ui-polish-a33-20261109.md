# Builder UI polish on the A33 (2026-11-09)

Press feedback, folding lists, the working indicator, the menu gesture and right-to-left layout, checked on the phone with the debug-only fixture screen (`UiFixtureActivity`), which fills the screen with demo, worst-case, empty or huge data through `UiState`. No model, worker or build was involved.

## Setup

- Phone: Samsung Galaxy A33 5G (SM-A336E), Android 16, arm64-v8a, 90 Hz.
- Builds: debug, before (`f1ed0c1`, SHA-256 `ab7d7070…91cb`) and after (`2653ca1`'s tree, SHA-256 `c4f21b29…dd453`), signed with the local test key and given a temporary, uncommitted app id suffix `.uipreview` so they installed beside the release 0.1.2 builder without touching it or its data. Installed with `adb install`, removed afterwards.
- Emulator: API 36 x86_64, 1080×2400 at 420 dpi, software rendering, for reduced motion only.
- Recording: `adb shell screenrecord` of one tap sequence on each build; frames inspected with ffmpeg. Raw footage stays local.

## Results

| Case | Before | After |
|---|---|---|
| Press and hold Stop | Box darkens slightly; the key looks disabled | Light wash at once, key scales to 0.95, wash fades on release |
| Tap a step group twice | Steps appear and vanish in one frame | Steps grow out of the row and fold back; a frame catches the fold half-way |
| Working step | Pulsing dot and counting dots | Pulsing dot only |
| Fling the menu shut | Closes | Follows the finger, keeps its speed and settles off-screen; no jump at release |
| Arabic per-app locale, menu | Tree lines and panel edge on the wrong side; a drag toward the edge does nothing | Lines and edge mirrored, folded marks point left, a drag or flick toward the edge closes it |
| Arabic per-app locale, chat | English text laid out right to left (".Before I start, three choices") | English left to right, Arabic right to left |
| Long free model name | "Llama 3.3 Nemotron Super 49B v1.5 (f…" | "Llama 3.3 Nemotron … (free)", in both directions |

Expanding and folding the 38-step worst-case group six times, `dumpsys gfxinfo`, debug builds:

| Build | Frames | 50th | 90th | 99th |
|---|---|---|---|---|
| Before | 9 | 150 ms | 250 ms | 250 ms |
| After | 102 | 17–18 ms | 30–31 ms | 250 ms |

The 250 ms frame is composing the 38 rows, in both builds. The animated frames are over the 11 ms budget of a 90 Hz screen in a debug build.

Release 0.1.3 on the same phone, six taps on a real chat's step group and then on its plan: 426 and 431 frames, 50th percentile 7 ms, 90th 13 ms, 99th 36 ms and 15 ms, 0.7% and 0% janky.

Emulator with all three animation scales at 0: the press wash still shows, the menu opens and a step group unfolds at once, the dot and cursor do not change between frames, and a drag still tracks the finger.

## Host

Controller 782 and worker 91 unit tests pass, Android Lint has 0 errors, and debug and androidTest APKs assemble. The 24 controller tests that read the platform jar needed `toolchain/input/android/android-36.jar`, copied from the SDK's `platforms/android-36/android.jar` (the same SHA-256 the app pins). `format` cannot run as committed: Spotless's `ratchetFrom` commit `4e3a340e…` is not in this repository's history. The changed files were formatted with the ratchet pointed at `main` for that run only.

## Not covered

- The soft keyboard did not open on the emulator, so the chat height with a long prompt, four pictures and both setup notes plus the keyboard was not seen. On the A33 without a keyboard the chat already gets about a third of the screen.
- A chat of 120 messages renders every message (no lazy list); on the emulator its frames were about 60% longer and it opened 1.1 s slower than the demo chat.
