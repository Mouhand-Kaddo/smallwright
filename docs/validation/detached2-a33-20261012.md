## Verifier failure and source correction

The first post-reconnect `verify2 --label 03` attempt is preserved at
`toolchains/alpha-goal-20261012/detached2/verify2-03.txt` with its original
handle. It returned host exit 0 and instrumentation code 0, with
`IllegalStateException stage=GUARD`. This happened before receipt/signature
verification and before any fixture pin write.

The cause is a stale-revision read in the test probe. `ProjectStore`'s
`readCurrentSourceBytes(expectedRevision)` requires the requested revision to
match the project's current HEAD. After the user's normal Build, HEAD is revision
2. The second fixture's shared source check and `fixture2()` both requested
revision 1 unconditionally, so they rejected the valid saved source as stale.
The correction reads the immutable snapshot at the observed current revision;
the armed phase still requires revision 1, `verify2` still requires revision 2,
and restore still revalidates the exact revision-2 receipt, APK bytes and signer.
Only `DetachedBuildProbe.java` changed. The original four phase implementation
is untouched. The failed verifier made no `verified` fixture pin write and did
not build, install or clear app data. The source correction was host-only and did
not touch the phone.

A later independent native check matched the installed and phone artifact bytes
and confirmed count 2 after restart, but reported cryptographic receipt
revalidation as pending the corrected phone verifier. A separate host-path guard
assertion from that check was corrected against the existing receipt contract;
its record says the generated artifact and installed bytes were unchanged. The
original `verify2-03` failure remains preserved and has not been rewritten as a
pass.
