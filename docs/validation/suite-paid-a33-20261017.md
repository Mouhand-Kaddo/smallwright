Date: 2026-10-17 Dubai. Device: Galaxy A33 5G (SM-A336E), Android 16/API 36.
The user approved paid requests with `deepseek/deepseek-v4.1-flash` on
2026-10-17. Controller `013f5e77…` asks OpenRouter only for providers charging
at most $0.30/$1.20 per million input/output tokens, uses low reasoning with the
reasoning text excluded, and allows at most 16384 output tokens for source
replies. It rejects any reply reporting a cost above $0.05. Under these caps one
request costs at most about $0.04. The probe stops sends once their bound reaches
$2. The app does not store reported costs, so each section gives the token count
and the cost bound.

`scripts/suite/suite.py`, with the exact previewed context hash. Generated APKs
were verified on the phone and streamed from `run-as` into `pm install` (debug
install, not Android installer consent). Checklists ran with the controller and
worker force-stopped, with taps and text through accessibility actions from the
controller test APK (`foreignUi`). These are agent observations, not human
acceptance. Raw output: `toolchains/alpha-goal-20261017/<run id>/`.

Run ids end in `_20` for this round. Round-one results stay in their own
records and ledger rows.

## Independent review of the paid-round code

Two reviewers read `8a8cc23..HEAD` without running anything:
`codex/gpt-5.6-terra` and `claudeAgent/claude-sonnet-5-5`. Both said a paid
request cannot be sent without the exact approved context hash, and that the
API key is not logged. Fixes in the next commit:

- A reply must now include `usage.cost`; before, a missing value passed the
  $0.05 check. OpenRouter documents `cost` as always present. Both reviewers
  raised this.
- `recoverOutcome` pins the run ids that existed before the initial send, and
  the hash that was sent. It accepts only the single run that appeared after
  the send, with that hash; before, it accepted any run in the project except
  the continued one. Both reviewers raised this.
- The context is limited to 65,536 bytes before sending. Before, a 128 KiB
  context could cost more than the probe's $0.04 send bound, even though the
  reply would then be rejected.
- `pinBaseline` after `restoreAccepted` checks that the head is still the
  restored revision and snapshot. `restoreAccepted` refuses early when files
  other than MainActivity.java differ from the accepted snapshot.
- The paid budget check now runs before a send is recorded as attempted.

Not changed:
- Older probes still look for `(free)` labels; they fail closed and send nothing.
- `suite.py` input edge cases; it is a developer script.

Checks: all controller unit tests and lint passed (88 warnings, unchanged). The
new controller `823c2736…` and test APK are installed on the A33. On the phone,
`accept` for records_05 passed again, and `recoverOutcome` on records_05, which
already had an outcome, was refused at RECOVER_OUTCOME. No paid request was made.

Round 2 (Codex, fix diff only) accepted these fixes and raised two warnings,
both fixed in the following commit:

- A reply must name `deepseek/deepseek-v4.1-flash` or its catalogue canonical

  newer `-20261017` build, is rejected. Codex argued that applying a proposal
  from an unapproved model is worse than discarding one paid reply. I had
  declined this check in round 1 and now agree.
- `ContextFilter` caps the serialized context at 64 KiB, matching the send cap.
  An oversized context is now refused before the Send dialog shows.

deliberate, and the model must then be re-approved.
