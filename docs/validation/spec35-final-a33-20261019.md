## Surprises

- The first Send did not register. At 10:53:12 I tapped Send, pressed Home and
  turned the screen off in one adb call; on waking the phone the prompt was
  still in the input and no run had started (no `RunService`, no request). A
  mis-scaled tap earlier in the session had also made the Menu button take the
  typed text as key presses, which only opened the menu. Waking the phone
  showed Samsung's "Accidental touch protection" cover, which also stayed over
  the lock-screen notification views (`04a`, `05a`), so the notices were
  captured from the shade after `wm dismiss-keyguard`. The second Send worked
  and is the only run counted. I cannot say whether the first Send was dropped
  by the same cover (the screen had not been locked yet) or by the tap landing
  while the keyboard was moving.
- The "Added library … Also …" step for Material lists dozens of transitive
  libraries as one long block of text (`06b`, `06c`, `06d`), several screens
  tall. Plain, not a failure, but a lot for a non-technical person.
- The generated app is drawn edge to edge (target SDK 36): the title and the
  first card sit under the status bar, and the + button overlaps the
  navigation bar (`07a`, `07d`). It still works.
- The model's closing reply starts with "Build succeeded. Here's what the app
  does now:", which is a little technical for the reply contract; the rest is
  plain.
- After the install the chat showed the "It works, keep it" button.
